# 医学 AI 产品经理知识库第一阶段实施计划

**Goal:** 在不调整产品页面和已有交互的前提下，完成一个职业角色的官方资料→证据化抽取→去重核验→Supabase→检索→报告引用闭环。

**Architecture:** 保留现有三大九细分映射，以独立职业角色关联多个方向。公开知识与个人档案隔离；来源、抓取版本、事实证据与职业关联分层，缺失字段保留 null，时效和适用范围参与检索过滤。

**Tech Stack:** 现有 TypeScript strict、zod、Supabase Postgres/RLS、Next.js API；不增加向量库或付费抽取服务。

## 范围与约束

- 本轮只填充 medical_ai_pm；映射为 LIMEN 编辑性关联，不修改 O*NET 官方映射。
- 五类：职业、招聘、升学、行业、学习。只将实际成功获取、片段可定位的事实入库；失败保留审计。
- 薪资、专业限制、考试条件与统计不可推断；旧招生年份不可推为当前报考资格。
- 不修改 UI，不扩展数字人场景，不更换已有匹配算法，不公开部署。
- 用户补充：主要调查中国信息；核心五类与报告默认仅中国资料，海外资料显式选择后作为补充。
- 用户已授权 Supabase 对接和实际存储；迁移只新增 kb_* 表/RPC，先核对远端历史和 dry-run。

## 实施与验收

- [x] 数据契约：`src/lib/knowledge.ts`、`data/knowledge/roles.json`；拒绝不存在方向、无证据事实、错误日期和网址，显式列出缺失字段。
- [x] 采集：受控HTTPS清单、超时/大小限制、正文/hash/URL规范化、片段核验及分类；动态招聘通过真实浏览摘录进入自动提取。
- [x] 存储：真实应用 `202610220003_knowledge_base.sql`，只读RLS、非公开原文；7来源8记录重复导入计数不变。
- [x] 检索：角色/方向/类型/关键词/地区/时效过滤，稳定引用与缺失；默认CN，未覆盖和失败显式区分。
- [x] 消费：R1/R2沿用证据快照；探索可调用API，不改前端。真实模型引用→私有保存→恢复已验证，完整个人主线未重验。
- [x] 测试：12知识单测、21真实存储/RLS检查、11检索案例、10真实模型引用检查、12 HTTP检查通过。
- [x] 集成：77全项目单测、lint、生产build、50文件密钥扫描、5组smoke通过；预览已恢复，当前摘要/问题/交接已更新。

结果与限制见 `docs/testing/knowledge-pilot.latest.md`。本阶段只证明试点流程闭环，不证明全国覆盖、个人资格或职业匹配效果；后续扩展等待用户下一阶段指示。
