# R1 / R2 报告与分析引擎

## 设计总则
职业兴趣是职业活动偏好，不是智力、技术能力、录取概率。医学科研成绩是经历证据，不代表职业兴趣。用户未填写 ≠ 零基础。职业兴趣与学习成本不能粗暴加权成一个无来源的“适合度百分比”。

## 输入层
A) O*NET 30题原始 answers + 官方 RIASEC + 官方职业列表（必须存version、返回时间）
B) UserProfile：含自由文本/课程/项目成果，以及字段级可选性
C) LIMEN 手工校审的一对多职业-研究方向映射及 skills/courses
D) 职业工作台的明确用户反馈与选择
E) 仅已核验的升学项目（有年份/官方来源）+ 年份/每周时间/升学路径

## 初步画像 R1（必须发生在专业体验之前）
- 官网原始 RIASEC 六维：数值/维度/来源；其代表的活动与职业例子
- 可迁移能力表：`skill`,`evidence_ref`,`status`（已自述/课程/项目/待确认），不得把技能完全归功于高校背景
- 职业技能匹配：按候选方向列出知识库职业/招聘原文要求的技能，逐项标注「有记录 / 仅自述 / 信息不足」；技能要求必须带 `record_id` 与原文 `quote`，只做名称/别名对照，不评分、不排序、不合成适合度
- 最多三个**探索方向**：`direction_id`,`related_onet_codes`,`rationale_evidence_refs`,`what_to_explore_next`；如果用户的最佳职业不在本地9方向内，也要显示“目录之外的兴趣方向”，不可强塞
- 证据不足/尚未了解的事情
- 明确 R1不下定论、不按时报考、不列虚构高校

## 完整报告 R2（用户选方向+完成体验后）
- 目标研究方向与主要职业任务的关联（标记“LIMEN编辑关联”）
- 兴趣依据：问卷、用户喜欢的活动、体验反馈，彼此独立
- 技能：已具备证据/主观自评/未知；课程和技能差距归入“待学习/已了解/待核实”而非全打0
- 方向对比：1个主目标+最多2个备选，注明哪些判断主观
- 课程依赖路线：如Python→数据处理→基础ML→项目；标明具体大学项目可另加数学/408等，不做统一课程要求
- 学习/科研/升学任务：每条必须有 `why`,`source`,`deliverable`,`dependencies`,`priority`,`estimated_effort_range`（无证据就留空，不乱填小时）
- 规划：根据 `transition_year`, `weekly_hours`, `pathway` 倒排，每月/每阶段安排，安排不现实时列风险和取舍；导师联系是可选策略、不是万能必须项
- 院校：仅列有官方证据的项目；无核验数据则输出搜索/核验任务，不能杜撰院校资格

## LLM 的边界
- **不调用 LLM 评分 Mini-IP**；官方API/已验计分规则产生 scores；所有数值结果确定性计算。
- LLM负责自由文本技能/兴趣“候选抽取”及结构化解释，引用 `evidence_ref`，使用 JSON schema 校验。
- LLM生成后做代码校验：所有 direction_id 属于映射表；O*NET编码存在；院校必须在 verifiedAdmissions 里；课程/技能来自方向目录或显式新增并标记草稿。

## 测试用例
T1 高兴趣但无CS课：呈现“兴趣值得探索，课程准备较多”，不能说“不适合”；T2 临床数据经验多但不喜欢编程：区分迁移能力和兴趣；T3 不确定是否转：允许继续医学；T4 空论文/GPA：仍可生成R1；T5 所有招生缺失：显示待核验，不编造；T6 API失败：给出错误/离线状态，不伪造官方成绩。
