## 四、几个不好找但必须修的缺陷

**1. 刷新瞬间局部变白（首页）**
逐帧截屏 183 帧定位：不是 canvas，是那张解剖图版在 JPG 解码前露出容器底色 `#f8f4e8`，
包围盒与元素 rect 完全重合，持续 137ms。用户说的"一个瞬间，然后出图"就是它。整块删除后复测，
加载全程无"先亮后暗"的瞬时块。

**2. 色键墨迹"画得再深落纸也淡"**
根因是原来用半透明 alpha 画墨，墨先与绿幕混色、再被抠掉一半。改成不透明实色四档表达浓淡、
密度靠笔数。深色像素 **2.08% → 9.16%**（线上实测），四形态间 17.5–19.5% 像素变化。

**3. 折叠里的内容永久停在透明**
滚动叙事层给将要入场的元素打 `opacity: 0` 起始态。收起的 `<details>` 里元素没有布局盒子，
IntersectionObserver 永远不触发 → 用户展开看到空白。`/explore` 实测 6 个 `<li>` 卡死。
修法：收起的 details 内不武装 + 展开时放行。修复前 6 → 修复后 0。

**4. 折叠展开后高度为 0**
曾用 `::details-content { block-size: 0 }` 做展开动画，实测展开后内容可见但 `<details>` 停在 47px、
内容溢出卡片。改成只动 opacity/translateY。实测 47 → 258 → 47px。

**5. WebGL 上下文丢失**
线上连续截图时上下文丢了 2 次，画布变永久空白。补 `webglcontextlost` 处理：preventDefault +
重建资源。告警消失。

**6. 收进折叠里仍然是堆砌（文库）**
单条来源记录的"展开原文摘录"原本 18148px。改成正文容器限高 + 内部滚动（原文一字未删）→ 495px；
折叠 75（含 65 嵌套）→ 41；每页记录 12 → 5；招生表格从常显改独立折叠（原本 2918px 表格
与下方列表是同一批数据重复渲染）。41 个逐个展开最大 1209px。

## 九、第二轮盲审（6.5/10）与整改

第二轮换了一位独立评审员，按同一份 oil-ui-pro 手册盲审，总分 **6.5/10**（上一轮 6.0）。

### 9.1 它推翻了我上一轮的什么

上一轮我把 `.t-section` 和 `data-xn-stagger` 接进了内页，并在交付说明里写成"内页动效已接线"。
**这个说法不成立。** 根因在 `xeniso-motion.tsx`：`setTimeout(release, 2200)` 会把所有仍在
`pending` 的元素一次性放成不透明。真实读者在第一屏停留 2.2 秒是必然的，所以往下滚时区块
早已不透明——错峰对读者根本不存在。评审实测 t=3.2s 时，视口下方 1131px 的错峰宿主已经是
`data-state="in"`，子项 opacity 正在视口外从 0.898 淡到 0.677。

也就是说：接线做了，但被兜底抵消了。**这是"改了但没效果"的典型，比没改更糟——因为它看起来已经完成。**

改法与实测见 9.2。

## 十、内页主视觉与首屏动作（第三轮）

第二轮盲审的核心判断是"首页是一个作品，整站还不是一个有特色的站"，判据是

### 10.1 把首页的墨迹场铺到内页页眉

复用 `InkField`（手写 WebGL fbm 着色器），不新造效果、不加依赖。它本身已经处理了
reduced-motion 只画一帧、离屏停帧、标签页隐藏停帧、DPR 上限 1.5、缓冲区 0.6 缩放，
工程质量够，直接垫到页眉底下。

接入 6 个页眉类：`xnlib-head` / `community-head` / `assessment-head` / `xd-head` /
`xp-head`（两处）/ `account-head`。`globals.css` 统一给它们
`position: relative; isolation: isolate; overflow: clip`，画布 `z-index: -1`。

两个必须踩对的点（都踩了）：

- **必须有 `isolation: isolate`**，否则 `z-index: -1` 的画布会退到页面背景之后被彻底盖住。
- **出血不能用负百分比 `inset` 配 `width: auto`**：算不出尺寸，实测画布塌成 14×7
  一个色块——正是 `InkField` 注释里第 1 条坑。改用 `inset: 0` + `scale(1.22)`。

### 10.2 墨迹强度是量出来的

先按 `opacity: .5` 上线，然后用 WebGL `readPixels` 在同一 rAF 内采样画布真实像素
（帧呈现后 drawingBuffer 会被清，必须帧内读），结果是：

| | 墨迹最深像素 | 合成背景 | h1 对比度 | body 对比度 |
|---|---|---|---|---|
| opacity .5（初版） | 227,222,204 | 228,219,195 | 11.94 | 9.53 |
| opacity .88（现行） | 227,222,204 | 218,207,179 | 10.64 | 8.49 |
| 纯纸色基线 | — | 241,234,217 | 13.74 | 10.97 |

`.5` 时墨迹和纸色几乎没差（等于白跑一个着色器）。提到 `.88` 后合成背景降了 23 个
亮度单位（看得出来），对比度仍有 8.49:1，是 AA 要求的两倍余量。**"看得见"和
"不压字"两个目标同时成立。**

- `/assessment` 主按钮 **y=827 → y=571**。两个问题：说明卡被 `.assessment-stage`

## 十一、第三轮盲审（6.5/10，持平）与整改

### 11.1 它推翻了我上一轮的结论：内页墨迹场是看不见的装饰

我上一轮报的是"合成背景 218,207,179、Δ 明显"。盲审换了验法——**在同一页内关掉
canvas 前后各截一帧、逐像素差分**——量出来是：

| | 我的上一轮说法 | 盲审实测 |
|---|---|---|
| 合成后 meanΔ | "23 个亮度单位，看得出来" | **1.65–1.83 / 255** |
| maxΔ | — | 26 |
| 竖向 8 段行均值 | — | 233,233,233,233,233,233,233,234（完全平直） |
| 画布中位像素 | — | 234.3 = 纸色本身 |
| /community | "应该也生效" | **0.01，被整个盖住** |

我错在哪：我是拿画布自身的像素去推算"合成后应该是什么样"，没有量真实合成结果。
推算与实现在这一步脱节了。**判据必须是实测，不能是推算。**

根因（拿到数字后能直接定位）：着色器里 `p = (gl_FragCoord - 0.5*uRes) / uRes.y`
按**高度**归一化。首页画布近正方形，p 的跨度合理；内页页眉画布是 768×120 的宽扁条，
p.x 跨度达 ±3.17，`r = length(p * vec2(.62,.95))` 被 x 主导，几乎整片落在
`smoothstep(1.15, 0.28, r)` 的暗角之外 → 全部还原成纸色。同一个着色器，首页 maxΔ 149、
内页 26，差的就是这个。

改法：加 `uBand` uniform。`uBand=1` 时把暗角收边从 `(1.15, 0.28)` 放到 `(3.4, 0.10)`、
放宽混色阈值。**首页 `uBand=0`，取值与改动前完全一致**，首页那套被盲审评为
"最难抄"的观感一点没动。

### 11.2 变可见是有代价的，代价要用对比度换

带宽系数先给 0.66，最暗墨迹落到亮度 137。这时压在它上面的文字：

| | 最暗墨迹处对比度 | AA 要求 |
|---|---|---|
| `--ink-2` 正文（51,48,42） | **4.08** | 4.5 |
| `--ink-3` 眉标（70,64,51） | **3.19** | 4.5 |
