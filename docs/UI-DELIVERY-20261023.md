## 一、先说清三件事

**1. 线上从来没有"坏"，是"空"。**
用真实 Chromium 打开线上站点做 DOM 诊断，导航栏、CSS、接口全都是 200，`site-nav` 四个链接一直在。用户看到的"没有导航栏"是另一回事：**手机端主导航被收进了汉堡按钮，而那个按钮没有任何文字提示**。这次给它补了「导航」两字（实测按钮 43×44、`::after` 内容为"导航"）。

**2. 首屏"没有之前好看"是量化可证的，不是感觉。**
把首屏截图逐像素统计，和用户认可的设计原型 `redesign/xeniso.html` 对比：

| 指标 | 旧版线上 | 新版线上 | 设计原型 |
|---|---|---|---|
| 彩色像素占比 | 17.2% | **46.2%** | 63.5% |
| 主色单一度（越低层次越丰富） | 49.6% | **42.0%** | 32.2% |
| 唯一色块数 | 218 | **257** | — |
| 均值 | rgb(232,226,210) | rgb(227,220,202) | rgb(222,214,190) |

根因是**移植时首屏主视觉整块丢失**：原型右侧的档案夹 + 四张插画卡 + 虚线串线 + 印章 + 手写批注，在 Next.js 版本里一个都不剩（`home-scene`/`home-card`/`home-art`/`home-folder`/`home-thread`/`home-tape` 全部 0 处命中）。首屏只剩文字和一层很淡的墨迹。

**3. 视频那条路走不通，我按技术实质做了替代。**
`video-gen` 需要 ChatCut 桌面端的 `submit_video`/`track_progress` 工具与付费额度，本会话没有。所以"绿幕循环动画 + 色键抠底 + 鼠标切换阶段"改成了**浏览器内实时实现**：程序化在纯绿幕上绘制墨迹 → 片元着色器逐像素色键抠底并去绿溢色 → 叠在纸面上 → 鼠标横向切四个阶段、纵向改浓淡、静止 3.2 秒自动巡游。比绿幕 mp4 更锐利、零加载、且真能跟鼠标变。

## 二、这一轮做了什么

### 首屏主视觉（新增 `home-scene.tsx`）
档案夹 + 四张带手绘 SVG 插画的步骤卡（个人画像 / 初步评价 / 职业体验 / 行动规划）+ 虚线串线 + 胶带 + 印章（显示"4 类方向 · 10 个去向"）+ 手写批注。全部内联 SVG，不额外请求图片，不依赖 canvas。

### 色键墨迹舞台（新增 `chroma-ink-stage.tsx`）
- 绿幕 `#00ff00` 上画四种墨迹形态：墨环 / 墨涡 / 脉迹 / 格纸，分别对应四步
- WebGL 片元着色器做色键：`alpha = 1 - smoothstep(0.04, 0.16, g - max(r,b))`，并对边缘去绿溢色
- 修掉一个真实缺陷：**预乘 alpha 用错**导致透明区域把绿色"加"到底图上，形成一层绿雾。修复前实测 `G−max(R,B) = +5`，修复后 `−9`（回到正常纸底），纯绿残留 0.00%

### 动效层（`motion.css` + `xeniso-motion.tsx`）
错峰入场（首屏 60/106/152/198/244/290ms 递增）、视差（墨迹 0→48px、内容反向 0→−22px）、纸片浮动（印章 6.6s、胶带 4.8–7s 错相、图钉 4.6s）、弹性曲线 `cubic-bezier(.34,1.56,.64,1)`、顶部滚动进度条、文字滚动带。

工程细节：动效用独立的 `translate`/`rotate`/`scale` 属性而非 `transform`，这样纸片原有的 `transform: rotate()` 倾斜不会被抹平；滚动回调只排帧、布局量在 `ResizeObserver` 里预量。

### 12 项原创微交互（`micro.css` + `micro-interactions.tsx` + `template.tsx`）
墨滴点击反馈、荧光笔划线、铅字逐字浮现、纸张跟随鼠标倾斜、磁吸按钮、装订线进度、抽卡、数字滚动、光标墨迹拖尾、盖章落下、段落压痕、路由级墨迹转场。

### 档案抽屉（`filing-drawer.tsx`）
把四步区改成**可以一格格拉开的档案抽屉**（用户提的方向）。原生 `<button aria-expanded aria-controls>` + `role="region" aria-labelledby`，默认第一格打开，键盘 Tab/Enter 可用，收起时 `visibility` 延迟翻转避免"看不见却能聚焦"。它替代了原先与抽屉内容重复的四张卡片——同时回应了用户"字太多"的抱怨。

### 图标系统（`icons.tsx`）
22 个手绘线描图标（24×24、`currentColor`、1.6 线宽），笔触对齐原型 `#home-art-*` 插画。已接入主导航、返回按钮、账户入口、四步抽屉标签。

## 四、必须如实说明的局限

**1. 未独立评审，不打视觉分。**
oil-ui-pro 的评审派发协议规定：没有能看图的独立执行者时，主 Agent 按同一手册自检，交付时写明"未独立评审"；没有实际画面时不打视觉分。本会话的执行环境无法读取图像内容，所有"视觉观感"结论都来自**可测量指标**（像素统计、DOM 几何、计算样式断言、对比度计算、lint），不是肉眼看图。**建议你自己打开线上站点看一眼首屏与四步抽屉**。

**2. 视频生成未做。** 原因见第一节第 3 点。若确需真视频文件，需在 ChatCut 桌面端生成。

**3. 残留问题**
- `src/app/report/report.css` 有 83 处字号 + 1 处 10px 未纳入阶梯（该文件属并行会话禁区，本轮未动）。
- `experience-social-redesign.css`（仅 /match）、`careerexplorer.css` / `xeniso.css` / `library-redesign.css`（全站无引用，死文件）未动。
- 档案图版标注 10px 是刻意例外：它贴在 160px 宽的小纸片上，提到 13px 会撑破纸片。单独开了 `--fs-plate-caption`。
- 首屏眉标（`p.atlas-label`）保留：它是本站 `.atlas-label` 档案栏目标签语言的一部分，lint 的"标题上方眉标"是启发式提示，按协议保留并在此说明理由。

**4. 一处 lint 提示已修**：`npm run lint` 曾因 `tmp/micro/chrome-*` 下浏览器扩展解包文件报 2261 个错误，已在 `eslint.config.mjs` 的 `globalIgnores` 加 `tmp/**`、`output/**`、`review-shots/**`。
