# Career Studio · 职业体验规格（聚焦质量）

## 设计原则
用户不是来参加专业考试，而是来了解该岗位**每天做什么、使用什么工具、面对哪些真实取舍**。不设计低龄化小游戏，不让LLM动态生造研究流程。每个任务有“项目目标 → 可操作工作 → 实时结果 → 个人成果 → 反思”。研究材料有来源，互动数据是合成教学示例要标注。

## 第一版建议只做一个高品质工作台
**统一医学场景：穿戴式心电预警研究原型**（合成信号，不用于诊疗）。优先做 `AI模型评价工作台` 或 `医学信号工作台` 中视觉/工程最稳的一项；二者都不能只是“选择答案”。完成再扩展。

**A AI算法工程师（适合当黑客松主Demo）**：给固定的合成50–100条病例样本（score / trueLabel / sourceDevice），拖动阈值（0.1–0.9）→实时计算 TP/FP/TN/FN、灵敏度、特异度、假阳性数；切换采集设备→外部验证表现变化；用户选择折中方案并生成导出评估卡。核心技能：数据集切分、模型评价、泛化、误报权衡。禁止把教学数字写成论文真实结果。

**B 医工/信号工程师（可后续）**：展示确定性合成心电信号 + 噪声。调采样与滤波参数→波形/失真/功耗估计变化→生成设备测试摘要。原理为教学模型、非医学器械性能认证。

**C 医学信息学（可后续）**：模拟报警事件进入医院：选择必要的临床上下文字段、通知策略、去重规则，实时观察重复报警数和医生工作量趋势→输出事件数据模型/流程图。不是“GLU是什么”的术语小测。

## 一致的数据合同
见 `data/experience_seed.json`：scenarioId、roles、fixtures、operations、outputs、reflection。每个 `operation` 必须对应可观察状态变化和具名技能。

## 体验后的反馈
- 「最想继续做的环节」（强制仅一次体验反馈）
- 「最不喜欢的环节」（可以“暂无”）
- 「是否愿意再花3小时做类似工作」五级回答
- 「想继续了解什么」开放填写
只把其作为**体验兴趣**证据。互动正确率、停留时间、点击次数都不作为“专业适配度”分数。

## 质量验收
至少三次状态变化、图表数据由用户参数实时驱动、结果可导出JSON或文本、文字解释对应实际变化、手机可操作、无“假滑块只改标签”等伪交互。能为完整报告提供来源可追溯的体验反馈。
